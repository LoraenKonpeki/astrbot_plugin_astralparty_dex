## 描述符与响应规则

`descriptors/dex` 下四份描述符与插件现有描述符逐字节一致，不需替换。runtime 与 Dex 的结构不能混用；资料包包含旧 runtime 定义，不能作为当前登录协议直接替换。

应按响应 UPSN 关联请求，UPSN 为 0 的包属于推送。成功响应还需校验已确认的 CMDID，错误返回先按 UPSN 归属处理。已明确的配对包括 5001→5002（连接）、5003→5004（心跳）、5153→5154（展示资料）、5155→5156（短战绩）、5263→5264（简要资料）。插件查询使用其中连接、展示和简要资料的显式映射，不使用通用 CMDID+1 推断。

实现了请求先登记再发送、请求 DOWNSN=0、UPSN 超出有符号 int32 后从 100 继续、心跳 tick 限制在 0x7fffffff。1001 踢下线推送立即关闭连接并阻止自动重连；10012 识别为版本错误，10020 识别为重复登录。用户需主动私聊刷新，避免与游戏客户端互相抢占。

## 业务边界与冲突证据

GetPlayerFightRecord 的 index 是短战绩条目的索引，不是历史战绩翻页参数，因此不增加“无限历史分页”。好友 5163、抽卡 5145、房间 5013 等候选接口尚缺业务和线上验证，不作为已可用功能发布。

报告中的 SDK init 不签名描述与上游实现及 v0.1.2 的实际初始化验证冲突：无签名返回“sign 参数不能为空”，签名后成功。因此继续为 init 签名，不套用报告中的无签名示例。

这些结论来自静态客户端分析和本地模拟测试。资料包没有提供真实账号联调证明；插件仍未完成真实短信登录、游戏实战回放及 QQ 现场联调。描述符相同也不等于当前服务器的所有功能均已验证。
